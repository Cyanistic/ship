staying afloat in an ocean of slop

ship is a small terminal workspace that gives you and your coding agents somewhere steady to work while everyone else keeps shipping more slop.

$ git clone https://github.com/shipmux/ship.git
$ cd ship && cargo install --path crates/ship

deck what works today

there are no releases yet, but a build from source does all of this today. linux and macos are the priority platforms, and windows is best effort.

  • work that keeps running

    a background server owns your terminals. close the window or press alt-q to detach, and everything keeps running until you come back.

  • saved tabs

    after a server restart or reboot, your tabs, splits and directories come back with fresh shells. programs, agent conversations and scrollback do not resume.

  • agent status

    agents that report their state, like claude code, codex and pi, get a sidebar entry showing whether they're working, blocked, finished unseen or idle, and their tabs show it too. a sound plays when one finishes or needs you while you're looking elsewhere, and alt-a jumps to it.

  • tabs inside tabs

    tabs can nest, so a big task can hold its own smaller ones. a sidebar shows the tree. fold the parts you aren't looking at, or drag rows to reorder and nest tabs.

  • split panes

    split, zoom, swap and resize from the keyboard, or drag shared borders to resize. new splits open in the directory you were working in.

  • more than one window

    attach from several terminals at once. each one picks its own tab and pane, while the work underneath is shared.

  • scrollback and copy

    scroll back through a pane's history, and drag to select and copy text.

  • a scriptable cli

    server actions are also ship commands that print json, so scripts and agents can create panes, read output and steer a specific client's selection.

  • agents driving agents

    ship pane send types a prompt or keys into a pane, and ship pane wait blocks until the agent there stops working, so one agent can hand work to another and read the answer.

  • your keys and menus

    rebind anything, build tmux-style prefix modes, and customize right-click menus for panes, tabs and the sidebar. let mouse-aware programs have right-clicks per pane. config changes apply when you save.

not built yet

  • releases and packages.
  • searching a pane's history, and a keyboard copy mode. for now, ship pane read --lines N | grep ... covers search.
  • resuming agent conversations or rerunning programs after a restart. saved tabs come back with fresh shells.
  • closing a pane automatically when its program exits.
  • connecting to another machine's server directly. the server only accepts local connections for now, so use an ssh tunnel.
  • testing on linux. most features have only been checked on macos so far.

waterline the ocean of slop why ship

this is the water everyone else keeps shipping into: readmes that promise everything, pull requests nobody read to the end, and features that exist because generating them was cheaper than deciding not to.

ship can't drain it, and it doesn't try. it keeps your shells, editors and agents in tabs and panes on a server that stays up after the window closes, and it tells you which agent is working, which one is stuck on a question and which one finished while you were looking somewhere else, so whatever you send out is something you actually looked at.

below deck how it works

ship runs in two parts, a server that owns the work and windows that look at it, and the rooms below follow from that.

a server that stays up

a background server owns your tabs, panes and the programs in them. running ship opens a window onto that server, and closing the window, or pressing alt-q, leaves everything running until you run ship again.

you can open ship from several terminals at once. the windows share the work, the same tabs, programs and output, but each picks its own tab and pane, folds its own sidebar and keeps its own mode. ship server stop ends the server and every program inside it.

tabs and panes

tabs can hold panes, other tabs, or both, so a big task can keep its smaller pieces underneath it, and the sidebar on the left shows the tree. a new split opens in the directory you were working in, and a program that exits leaves its pane open with its output so you can read what happened.

agents that report their state get an entry in the lower half of the sidebar, with the ones that need you sorted to the top. tabs show the most urgent icon from anything inside them, so a blocked agent stays visible even in a folded tab.

a cli that prints json

anything you can do with keys you can also do with ship commands. they print json and take explicit ids, so a script never acts on whichever pane you happen to have selected, and inside a ship pane the commands default to the pane they run in.

agents driving agents

ship pane send types a prompt or keys into a pane, and ship pane wait blocks until the agent there stops working. that is enough for one agent to start another, give it a task and read the answer.

--wait returns once the agent has stopped working, and the state it prints says how the turn ended: done or idle means it finished, and blocked means it is asking you something. this works with any program that reports its status.

install

there are no releases yet, so ship builds from source. you need:

  • a recent stable rust toolchain
  • zig 0.16 on your PATH, to build ghostty's terminal library
  • git and a network connection on the first build, which fetches ghostty's source
  • on linux, pkg-config and alsa's development headers for sound (libasound2-dev on debian and ubuntu, alsa-lib-devel on fedora)
$ git clone https://github.com/shipmux/ship.git
$ cd ship
$ cargo install --path crates/ship

run ship. it starts a server in the background if one isn't running, restores its saved tabs, and opens on the first tab's first pane. press alt-q to detach, and ship brings you back.

on macos, set your terminal to use option as alt, often called "option as meta", or ship's keys will type special characters instead.

keys

all of ship's default keys are alt chords, and any other key goes to the program in the selected pane.

default keys
alt-nnew tab with a shell
alt-shift-nnew tab nested under the current one
alt-xclose the tab
alt-| alt--split the pane right or down
alt-shift-xclose the pane
alt-left alt-rightprevious or next tab
alt-h j k lmove to the pane left, below, above or right
alt-tabnext pane in the tab
alt-ajump to the next agent that needs you
alt-shift-h j k lswap the pane with its neighbor in that direction
alt-fzoom the pane to fill the tab, or unzoom
alt-rresize mode: h j k l move the pane's edge, esc leaves
alt-gtabs mode: j k move, h l fold or unfold, esc leaves
alt-bhide or show the sidebar
alt-pageup alt-pagedownscroll the pane up or down a page
alt-qdetach

the mouse works too: click a pane, a tab or an agent to select it, scroll with the wheel, drag to select and copy text, and drag borders and sidebar rows to resize and move things. right-click for actions.

config

ship reads ~/.config/ship/config.toml, or $XDG_CONFIG_HOME/ship/config.toml. without one it uses its defaults, and a running window picks up changes as soon as you save.

[server]
shell = "/bin/bash"   # default: your login shell

[client]
sidebar_width = 40

[client.modes.normal.keys]
"alt-q"  = {}  # alt-q reaches the program
"ctrl-b" = { action = { client.mode = "prefix" } }
# tmux habits

[client.modes.prefix]
kind = "oneshot"   # back to normal after one key

[client.modes.prefix.keys]
"c"      = { action = { server.tab.create = { starter = "shell", select = true } } }
"ctrl-b" = { action = { client.send = "ctrl-b" } }

ship config check points at the first mistake in the file, with its line and column.
